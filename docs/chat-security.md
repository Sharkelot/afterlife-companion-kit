# Tamsin chat guard

`guide-service/guard` is an Afterlife High-specific security policy, not a general-purpose content moderation product. Public chat remains disabled by default. Do not set `GUIDE_PUBLIC_MODE=1` until the owner has reviewed the report and approved release. No model weights are in this repository.

Flow: NFKC scrub and PII redaction → heuristic/CPU ONNX injection classifier → scoped policy (3-second local judge only for ambiguous topics) → untrusted-user delimiters in a canary-bearing system prompt → complete-response inspection → plain-text SSE and per-sentence HMAC TTS tokens. A guard exception/timeout refuses; no partial model text or TTS is emitted. The SSE endpoint buffers the whole completion, so the text is not truly incremental. Client history is not accepted or persisted. Only signed, static navigation facts are loaded; `GUIDE_SITE_MAP` is not used by this guarded endpoint.

Setup (private, CPU): create a dedicated Python venv with `onnxruntime`, `transformers`, `sentencepiece`, and `numpy`. Download `protectai/deberta-v3-base-prompt-injection-v2` using `huggingface_hub.snapshot_download(..., allow_patterns=["onnx/*", "LICENSE"])` outside the checkout. Set `GUIDE_GUARD_PYTHON` to that venv's Python and `GUIDE_GUARD_MODEL_DIR` to the downloaded `onnx` directory. Verify `onnx/model.onnx` SHA-256 `f0ea7f239f765aedbde7c9e163a7cb38a79c5b8853d3f76db5152172047b228c`. Its downloaded LICENSE is Apache-2.0 (SHA-256 `59899c6091b540582ed617e8eeaac4919dc985ccfc35459ee9752b699be5205b`). Without the classifier, chat fails closed.

Signed `guide-service/guard/sitemap.json` and `guide-service/widget/tours/tours.json` are verified at startup against the committed Ed25519 public key and `.sig` files. Their signing private key is not deployed or committed. If changing either file, have the site owner sign the exact new bytes and update the public key and both signatures together. A signature mismatch prevents startup. The example destinations and allowlisted URLs are Afterlife High-specific; do not use this policy for an unrelated site without replacing/re-signing and retesting them.

Public prerequisites: configure `GUIDE_TURNSTILE_SITE_KEY`, `GUIDE_TURNSTILE_SECRET`, and `GUIDE_PUBLIC_SECRET`, provide the local chat model, and get explicit approval. Set the widget script's `data-turnstile-site-key` to the matching public site key; it renders Turnstile per request and never falls back to mock/private chat on verification failure. The embedding site's CSP must permit `script-src` and `frame-src` from `https://challenges.cloudflare.com`; this repository does not change an external host's CSP. Turnstile is verified server-side on every public chat request (stricter than first-turn-only; the widget supplies a fresh token for each request). Per-IP rate limits, queue cap, and per-session token budget apply. `GET /admin/guard` only accepts a direct 100.64/10 client address; other clients get 404, regardless of forwarded headers. Never expose the administrative route through a reverse proxy that masks client addresses as tailnet. Counters and last 200 block reasons use a keyed session hash and never store message text.

Run offline tests: `pytest -q`; opt-in classifier test: `GUIDE_TEST_REAL_CLASSIFIER=1 pytest -q guide-service/tests/test_guard.py -m slow`. See upstream `guide-tts/guard/REPORT.md` for measured latency and 27B smoke results. Heuristics and classifiers are probabilistic, and unexpected topics or output can still slip through; leave public chat off pending review.
